## 1. Instalación de un servidor DNS

El objetivo de esta práctica es realizar la instalación y configuración de un servidor de DNS. Para ello necesitaremos una máquina virtual con sistema operativo [Ubuntu Server](https://www.ubuntu.com/server), y un cliente que deberá estar instalado y configurado con el usuario de la instalación que indique el profesor, o con nuestro nombre.

Se deberá llevar a cabo la instalación y configuración del servicio de DNS (bind9) bajo el dominio que el profesor indique, o elegido por el alumno. El cliente se configurará para consultar dicho servidor xxxxxxxxxxxxxx

### 1.1. Arquitectura web con un único servidor
En esta práctica vamos a trabajar con una arquitectura web basada en un servidor y un cliente.

### 1.2. Tareas a realizar

Realizar la instalación de Webmin para el sistema operativo Ubuntu Server, que se estará ejecutando en una máquina virtual de [VirtualBox](https://www.virtualbox.org/).

A continuación se describe brevemente las tareas que tendrá que realizar.

1. Actualizar los respositorios
2. Instalar el servicio de DNS y las utilidades necesarias `bindsoftware-properties-common` y `apt-transport-https`
3. Configurar las zonas (directa e inversa) del servidor en `/etc/bind/named.conf.local`:

```bash
//
// Do any local configuration here
//

// Consider adding the 1918 zones here, if they are not used in your
// organization
//include "/etc/bind/zones.rfc1918";

// Zona directa (forward zone)
zone "midominio.com" {
    type master;
    file "/etc/bind/zones/db.tudominio.com";
    allow-update { none; };
};

// Zona inversa (reverse zone) - Opcional, ejemplo para red 192.168.0.x)
zone "0.168.192.in-addr.arpa" {
    type master;
    file "/etc/bind/zones/db.192.168.0";
    allow-update { none; };
};
```

4. Instalar Webmin
5. Configurar el cortafuegos
6. Ejecutar Webmin

> IMPORTANTE
> En Ubuntu, la cuenta de `root` no está activada, pero habrá que ser `root` para poder hacer cambios en la configuración de los servicios. Por ese motivo, habrá que asignar la contraseña del usuario root de Webmin. Para ello, ejecuta la orden:
> ```bash
> $ sudo /usr/share/webmin/changepass.pl /etc/webmin root contraseña
> ```
> Sustituye `contraseña` por la que quieras asignar.

### 1.3. Entregables

Deberá crear un repositorio en [Github](https://github.com/) con el nombre de la práctica y añadir al profesor como colaborador.

El repositorio debe tener el siguiente contenido:
* Un **documento técnico** con la descripción de todos los pasos que se han llevado a cabo.
* Los **scripts de Bash** que se han utilizado para automatizar la instalación y configuración de Webmin, así como de las herramientas adicionales.

Además del contenido anterior puede ser necesario crear otros archivos de configuración, que deberán ser documentados e incluidos dentro del entregable. A continuación se muestra un ejemplo de cómo puede ser la estructura del repositorio:

```
.
├── README.md
├── images
└── scripts
    ├── .env
    └── webmin-install.sh
```

#### 1.3.1. Documento técnico
El documento técnico `README.md` tiene que estar escrito en Markdown y debe incluir como mínimo los siguientes contenidos:

* Descripción de la instalación de Webmin
* Cada descripción debe ir acompañada de **alguna/s captura/s de pantalla**, donde se pueda ver claramente los pasos que se han llevado a cabo.

#### 1.3.2. Scripts en Bash
El directorio `scripts` debe incluir los siguientes archivos:

* `.env`: Este archivo contendrá todas las variables de configuración que se utilizarán en los scripts de Bash.
* `webmin-install.sh`: Este archivo contendrá todas las instrucciones para automatizar el proceso de instalación de Webmin.
* 

## 1.4. Anexo. ¿Cómo gestionar los archivos .env?
Los archivos `.env` son archivos de texto que se suelen utilizar para almacenar variables de entorno con información sensible, com contraseñas, claves de API, etc.

Estos archivos no se deberían subir a un repositorio público, porque cualquier persona podría acceder a ellos y obtener las contraseñas que contienen.
